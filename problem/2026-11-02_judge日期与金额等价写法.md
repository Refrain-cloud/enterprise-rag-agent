# 【面试可讲】judge 也会被"同一天、同一笔钱"骗：日期与金额的等价写法

- 日期：2026-11-02
- 状态：已解决

## 现象

`agg_14` 的必答点写"UPS 负载最高出现在 **2026-09-16**"，助手回答写"出现在 **2026年9月16日**"，judge 抽取阶段判为 missing。金额同理：必答点写"111,000 元"、回答写"11.1 万元"时可能互相判不出。

## 原因

- `_norm()` 用 `[\W_]+` 去掉所有非词字符，日期连字符和小数点一并消失；`_number_in()` 只做字符串包含比较。
- 于是 `09` 无法匹配 `2026年9月16日` 里的 `9`（前导零），`111000` 无法匹配 `11.1万元`（单位不同，且小数点已丢失）。
- `_looks_like_contradiction()` 也按原始数字串比较，`09` 与 `9` 会被当成不同数值，存在误报矛盾的风险。

## 解决方案

- 新增 `_numeric_values()`：从原文抽取数值，`万/亿` 归一成基本单位，返回数值集合。
- `_number_in()` 现在接受**原文**（保留小数与单位），先做原有字符串/分段比较，再做数值比较；调用点从 `_canon(window)` 改为 `window`。
- `_claim_numbers()` 把带"万/亿"的数量换算成基本单位（`11.1 万元` → `111000`），保证正反两个方向都能命中。
- 矛盾检测复用同一数值集合，`2026-09-16` 与 `2026年9月16日` 不再被判为数字冲突。
- 新函数加入 judge 指纹覆盖，判定语义变化可被追踪。

## 验证结果

| 用例 | 结果 |
|---|---|
| `09` vs `2026年9月16日` | 命中 |
| `111000` vs `11.1 万元` / `111,000 元` | 双向命中 |
| `agg_14` 用中文日期回答复判 | 4 个必答点全部 covered，2 分 |
| 全量 120 题 | 见 `docs/handoff/2026-11-02_*.md` |
