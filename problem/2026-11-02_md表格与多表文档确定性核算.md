# 【面试可讲】md 表格不是"能看见的表格"：空行、多表与分组假设

- 日期：2026-11-02
- 状态：已解决

## 现象

`IT-014`《云资源成本月报（2026年9月）》是 md 文档，正文表格用空行分隔每一行、表头也不以 `|` 开头。问"本月云资源成本合计多少"时，表格工具完全不介入，全部回退 RAG。

同轮还发现 `SC-007` 增值税发票扫描件一页内含两张表（购买方信息表 + 货物明细表）。按列名直接拼接两张表后，明细表的金额列被购买方表的空值稀释，数值比例低于阈值，金额列不再被识别为可汇总列。

## 原因

1. **格式白名单过窄**：`TEXT_TABLE_FORMATS` 只有 pdf/png/jpg/jpeg，md/txt 从不进入确定性核算。
2. **解析器假设过强**：要求表头以 `|` 开头、数据行连续、分隔行紧跟表头；md 实际排版常是"表头 / 空行 / 分隔行 / 空行 / 数据行"。
3. **一文档一表假设**：所有解析结果按列名 `concat`，异构表互相污染。
4. **分组列假设过强**：只认"一号工厂 / 三号车间"这类实体行；成本项目表的分组是"计算 ECS / 带宽"这样的普通行标签，永远匹配不到。
5. **合计行会重复计数**：表尾"合计"行若当作明细行，总额会翻倍。

## 解决方案

- 白名单加入 `md`、`txt`；`_is_md_header` 跳过空行识别"表头 + 分隔行"，数据行允许跨空行。
- 解析结果按**列结构签名**分组：同构表（扫描件续页）合并，异构表（发票购买方表/明细表）分别核算，第一张能算出结果的表生效。
- 分组列选择改为**实体优先、行标签兜底**：实体行按出现行数打分，普通表按行标签去重数打分；纯数字、百分比、带标点或过长的文本不作为分组名。
- 单独识别 `合计/总计/小计/汇总` 行：从明细中剔除，并作为 `declared_total` 与逐行合计对照。
- 普通（非实体）表格加严格闸门：必须同时满足"题目点名唯一数值列 + 表内存在合计行 + 题目明确问合计/汇总"，避免把 `scan_05` 这种多字段题误算成一个总额。
- 单位优先取表头括号（`本月(元)`）或字段名提示（金额/费用/成本 → 元），金额保留小数，不再被 `:g` 截成 6 位有效数字。
