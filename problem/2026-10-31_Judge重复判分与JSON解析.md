# Judge 重复判分、JSON 解析失败与改写找回

- 日期：2026-10-31
- 状态：已解决
- 影响范围：`eval/run_eval.py` 的 judge 调用、事实点找回、复判 CLI；`build/eval/report*.json/md`
- 【面试可讲】亮点：同一个回答在 temperature=0 下重复判分仍会给出不同分数；单次判分不能当权威基线。修复分三层：**容错解析**（模型把原文引号塞进 JSON）、**确定性找回**（标识符数字误当日数量、跨句同义改写）、**重复判分取众数**（`--judge-repeats 3`），并用离线差分确认改指标没有误放事实。

## 现象

1. 全量复判出现 `multi_04` 的 `score=None`，reason 为 `judge failed: Expecting ',' delimiter: line 1 column 118 (char 117)`；judge 自带 3 次重试，但每次拿到同样的坏 JSON，重试无效。
2. `multi_03` 的 K2“河图投入约 11 人月、成本约 96 万”、K4“河图终止后人员转入凤凰”，以及 `multi_07` 的 K3“客户要求 9 月前上线重试机制并提供监控”被判 `missing`，但回答原文分别写了“累计投入 11 个人月、约 96 万元”“人员直接并入凤凰团队”“确保该改进于 2026 年 9 月前上线”“提供报警送达率监控看板”。
3. `ref_02` 的自动事实点在重复判分时状态不稳定；`ver_02` 与 `perm_01` 在不同全量复判批次间出现 1/2 分互换。定向 3 次判分：`ver_02` 为 2/2/2，`perm_01` 为 1/1/1；两次全量复判又分别给出 `ver_02=1`、`perm_01=1→2`。

## 原因

1. **JSON 未转义**：judge 把回答中的原文引号（如 `"71/86 通过"`）直接写进 JSON 字符串，`json.loads` 在字符串内部遇到未转义的 `"` 就报“Expecting ',' delimiter”。temperature=0 下重试得到相同输出，指数退避重试没有意义。
2. **二字词找回不覆盖跨句/近义改写**：`_recovery_window` 原实现要求“全部数字命中 + 二者词覆盖率”，而“投入约 11 人月”到“累计投入 11 个人月”、“转入”到“并入”、“9 月前上线”与“监控看板”分处两句时，字面覆盖率低于阈值。
3. **标识符数字污染**：旧实现用 `\d+` 直接抽数量，`V1`、`V3.2.2`、`HR-002`、`S1` 里的数字会被当成事实数量，导致找回窗口必须包含这些“假数量”，进一步降低找回率。
4. **单次判分有采样方差**：即使 `temperature=0`，同一回答在不同批次仍会得到不同事实点状态或分数。一次判分的结果不能直接作为权威基线，尤其当分数处在 1/2 边界时。

## 解决方案

1. `_parse_judge_json` + `_escape_inner_quotes`：首次 `json.loads` 失败时，用状态机扫描字符串内部非结构性的 `"` 并转义后重试；结构完整的 JSON 不走该路径，不改变 judge 语义。
2. `_claim_numbers`：先用正则剔除 `V1.0` / `V3.2.2` / `HR-002` / `S1` 等标识符，再抽取独立数量；`18K`、`71/86`、`2025-10` 这类真实数量保留。
3. `_word_level_recovery`：jieba 切分后按实词覆盖率找回，要求实词覆盖 ≥ 80% 且所有独立数量命中；只在 `status=missing` 时启用，且含否定词的事实不走该路径，避免“不愿承担/愿意承担”因实词重合被误判覆盖。
4. `--judge-repeats N` + `_modal_judgement`：每题重复判分 N 次，先按分数取众数，再按事实点状态组合取众数；权威基线使用 3 次投票。`--judge-stability` 保留用于单独量化逐题一致率。
5. 不为单题写 judge 规则，也不反复重跑单题挑高分；`ver_01`、`perm_01` 仍是真实答案缺口，保持 1 分。

## 验证结果

- **离线差分**：用已存 judge 输出对所有 60 题重算，找回规则只翻正 3 个事实点（`multi_03 K2/K4`、`multi_07 K3`）；`ver_01 K2` 仍 missing；所有无 `key_facts` 的拒答题不参与找回，权限题与库外拒答不受影响。
- **JSON 容错**：`multi_04` 重新判分后 5 个事实点全部 covered，`score=2`；用“字符串内引号 / 已转义引号 / 空串”三个边界用例验证解析器。
- **全量复判**：`score=None` 从 1 题降为 0；单次复判平均分 1.967（58×2 / 2×1），另一次单次复判为 1.950（57×2 / 3×1），差异来自 `ver_02`/`perm_01` 的判分翻转。
- **3 次众数基线**：平均 **1.950**（57×2 / 3×1），分数一致率 **58/60 = 0.967**；不一致题只有 `ver_02`（`[1,2,1]`）与 `perm_01`（`[1,1,2]`），均取众数 1。权威结果已聚合到 `build/eval/report.json/md`、`results.jsonl`。
- **稳定性**：`ver_02`/`perm_01`/`multi_03`/`multi_04`/`multi_07` 在同一批次内 3 次判分分数一致率为 1.0，但跨批次仍会翻转（`ver_02` 定向批次为 2/2/2，全量批次出现 1）；事实点层面 `ref_02` 的自动事实点状态也会变化但不影响分数。结论：单次判分不能当权威基线，应使用重复判分众数。
