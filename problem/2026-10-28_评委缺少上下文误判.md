# LLM 评委缺少检索上下文，把正确补充当成编造

- 日期：2026-10-28
- 状态：已解决
- 影响范围：`eval/run_eval.py` 的 judge

## 现象

fact_05 问“北辰云 MES 支持哪些部署方式”，标准答案只有“私有化、混合云、SaaS 标准版”。模型回答三种方式，并补充了适用客户、硬件要求等原文中确有的细节，评委却判 0 分，理由为“超纲、编造”。

## 原因

judge 只拿到问题、角色、标准答案和模型回答，看不到检索到的原文。它把“标准答案未提及”等同于“编造”，对补充了正确背景的回答产生系统性误判。

## 解决方案

1. 把本次检索返回的 top-k 原文（含 doc_id、状态、密级）一并传给 judge，最多每块 1,200 字。
2. 调整评分说明：资料中真实存在、且不与标准答案矛盾的补充细节不算编造；只有无依据或与资料矛盾的内容才算编造；`draft` / `superseded` / `outdated` 不得当作既定事实。

## 验证结果

重跑评估后，fact_05、multi_01、term_01 等“回答正确但补充了原文细节”的题目不再被误判。
