# 【面试可讲】评估框架两处修复：答案正确却被判 0，以及复判报告崩溃

- 日期：2026-11-01
- 状态：已解决
- 亮点：拒答题的“拒答”不能只靠模型自报，标记词表漏一个同义表达就会把正确回答判成 0；评估器本身也需要被验证。

## 一、拒答题答案正确却判 0

### 现象

`ref_08`（“老系统 3 年数据最终确定要迁移吗？”）答案明确写：

> 截至当前，老系统中 3 年数据是否迁移的问题**仍未最终确定**……结论：**未确定是否迁移**。

但 judge 判 0，原因是 `refused=False`。该题 `expect_refusal=true`，评分逻辑要求先识别为拒答，否则直接 0 分。

### 原因

拒答识别分三层：

- `REFUSAL_MARKERS`：通用，用于自动标记；
- `STRICT_REFUSAL_MARKERS`：无条件判定为拒答；
- `ABSENCE_REFUSAL_MARKERS`：只在 `expect_refusal=true` 时补充判定。

前两层只覆盖“无法确定”“未提及”“不存在”等说法，没有“未最终确定”“未确定是否”这类表达。答案回答得越自然，越容易漏判。

### 解决方案

在 `ABSENCE_REFUSAL_MARKERS` 增加 `未最终确定`、`尚未确定`、`未确定是否`、`尚未最终确定`。该列表只对 `expect_refusal=true` 的题生效，不会把普通题的“某细节未确定”误判为整体拒答。

### 验证结果

| 项 | 结果 |
|---|---|
| `ref_08` 复判 | 2 分，3 轮一致 |
| 120 题拒答正确率 | 1.000 |
| 其余 15 道拒答题 | 无回归 |

## 二、`--rejudge` 报告写入崩溃

### 现象

复判 `agg_13,ref_08` 时判分完成，但写报告阶段报错：

```
KeyError: 'generation'
  at _write_markdown: cost['generation']['total_tokens']
```

`results_rejudge.jsonl` 已写出，`report_rejudge.json` 已写出，但 `.md` 未更新。

### 原因

全量报告的 cost 结构含 `generation / judge / total / per_question`，而复判只统计 judge 与 embedding，`_judge_cost_summary` 不返回 `generation`，`per_question` 也没有延迟字段。`_write_markdown` 无条件读取这些键。

### 解决方案

- 只有 `cost.get("generation")` 存在时才输出“生成 token”行；
- `per_question.avg_latency_s` 存在时才输出延迟行；
- judge 与总费用保持必选。

### 验证结果

`--rejudge --ids ref_08 --judge-repeats 3` 正常产出 `report_rejudge.md`，无异常。
