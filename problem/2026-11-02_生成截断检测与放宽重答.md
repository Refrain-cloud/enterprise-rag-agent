# 【面试可讲】答案停在半句：用 finish_reason 识别截断，只对命中的题放宽预算

- 日期：2026-11-02
- 状态：已解决

## 现象

`multi_04`、`multi_09` 的 `completion_tokens` 恰好停在 900，回答在“费用责任”“二、账号和邮箱”处中断，后续必答点全部缺失。两题都因此只拿 1 分，但检索、引用、忠实率均为满分，容易被误判成“模型不会答”。

## 原因

- `src/agent/ask.py` 把生成预算写死为 900（表头/明细题 1200），没有检查 `finish_reason`。
- 同题重复生成并不总是撞到上限：`multi_04` 在三轮观察中都以 900 完整 `stop`，而基线那一轮在 900 处 `length`。温度 0 + seed 仍存在服务端采样差异，不能假设“同一题只会出现一种长度”。
- 截断是静默失败：HTTP 请求成功、usage 正常，只有答案末尾缺内容；judge 只会少判几个必答点，不会报错。

## 解决方案

- 新增 `_generate_complete()`：每次生成后读取 `choices[0].finish_reason`；只有 `length` 才用同一消息、同一 seed 把预算翻倍重答（900 → 1800 → 2400）。
- 预算移到 `src/config.py`：`RAG_MAX_TOKENS`（默认 900）、`RAG_MAX_TOKENS_HEADER`（默认 1200）、`RAG_MAX_TOKENS_CEILING`（默认 2400）。
- 结构化字段重写也走同一函数；首次生成若发生截断，先补全再判断字段违规，避免对半截答案做格式校验。
- 结果中记录 `generation_check.truncation`（每次的预算与 `finish_reason`）和 `retried_on_truncation`，评估日志在仍截断时输出 `truncated_at=...`。
- 只对命中截断的题多付一次生成费用；正常题的行为与成本不变。

## 验证结果

|---|---|

| `multi_09` 冒烟 | 900 `length` → 1800 `stop`，答案完整，2 分 |
| 五题 `--gen-repeats 3` | `multi_04`、`multi_09` 均 `[2,2,2]`；`multi_09` 代表轮触发一次截断重答 |
