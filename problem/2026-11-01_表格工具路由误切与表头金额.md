# 【面试可讲】表格工具路由误切：关键词、0 行结果与表头金额

- 日期：2026-11-01
- 状态：已解决（待 120 题全量复验）

## 现象

120 题 v4 冒烟（仅生成、不判分，费用 0.5176 元）暴露 6 道题的表格工具误切：

| 题号 | 问题 | 误切表现 |
|---|---|---|
| ver_19 | QT-003/QT-005 表头金额与明细合计是否一致 | 走 SQL，把 `_summary` 合计行当成表头金额，回答“两份都一致”（实际 298,000 vs 348,000、380,000 vs 398,000） |
| chat_05 | UPS 电池为什么选 A 家不选报价最低的 B 家 | 因“最低”命中聚合词，走 SQL 查了无关的巡检表 |
| ref_09 | 换线时间统计报表什么时候上线 | 因“统计”命中聚合词，走 SQL 返回 0 行，回答“未查询到” |
| agg_16 | 云资源成本合计、环比、异常 | 正确答案在 markdown 月报 IT-014，却对预算表 XS-001 生成 SQL；数值列全空仍作为答案 |
| agg_14 | UPS 负载最高 + 还提示哪些问题 | SQL 第二分支只取日期与备注，转述丢了“端口 22/24” |
| agg_16（第二次） | 同上 | 生成 SQL 报“只允许单条语句”，回退 RAG 后反而答对 |

## 原因

1. `is_aggregation_question` 只看聚合关键词（最高、统计、最低等），没有要求“明确数值诉求”，比较级和版本问题也会命中。
2. 表格工具把“SQL 能执行”当成“结果可用”：0 行、或金额/数量列全为 NULL 时仍交给模型转述。
3. CSV 的表头金额写在正文说明行，`table_loader` 只把它放进 `notes`，不进明细表；SQL 无法区分表头与 `_summary` 合计行。
4. 数值 + 叙述混合题（“还提示哪些问题”“主要异常是什么”）走 SQL 后，转述容易丢掉备注里的细节。

## 解决方案

- 路由加前置条件：问题必须含数值诉求（多少/几笔/合计/金额/占比/平均等），且排除版本权威性问题、“表头金额对比”和“还提示/主要异常”类混合叙述题。
- `answer_with_tables` 增加两道结果校验：`row_count == 0`，或以金额/合计/数量等命名的列全部为空时，回退 RAG。
- 表头金额题改走 RAG，并在系统提示词中要求逐份文档用两三行写出表头金额、明细合计、差额和结论，禁止用汇总行冒充表头；该题型单独放宽 `max_tokens` 到 1200。
- SQL 提示词补充：问“还提示哪些问题”时必须返回检查项、读数、日期和备注。

## 验证结果

| 用例 | 修复后 |
|---|---|
| ver_19 | RAG，2 分（逐份列出 348,000 vs 298,000、398,000 vs 380,000 及差额） |
| agg_14 | RAG，2 分（含端口 22/24 与三处备注） |
| agg_16 | RAG，2 分（111,000 元、环比 +4.2%、带宽异常） |
| chat_05 / ref_09 | 不再走 SQL，RAG 回答 |
| 68 题 v3 路由 | 新旧 `is_aggregation_question` 逐题比对，0 处变化，v6 基线仍有效 |

剩余已知噪声：`agg_14` 曾因判分器不认“2026年9月16日”与“2026-09-16”等价而记 1 分；`ver_19` 的格式检测把“报价范围”误当字段名（仅观察指标，不影响答案）。
