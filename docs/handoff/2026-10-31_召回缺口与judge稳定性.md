## 已完成

### 1. ver_01 召回缺口：不是排序问题，是权限与标注冲突

- 现象：`ver_01` 的 gold 文档 HR-010 未进 top-12，原计划排查版本/状态过滤与 BM25/向量排序。
- 根因：
  1. HR-010 为 `confidential`、`scope=dept:HR`，普通员工在检索层就不可访问；正文也写明“仅 HR 与部门负责人可见”。要求普通员工召回它，等于要求突破权限。
  2. 同一轮排查发现诊断脚本统计“首次命中排名”时用字典推导保留了**最后一个** chunk 的排名，重复 chunk 覆盖了靠前的排名，制造了大量假缺口。
- 处理：不放开 HR-010、不调检索；把它从 gold 移到 `supporting_doc_ids`，修正诊断脚本用 `setdefault` 保留首次出现。
- 同批修正另外 3 道过宽的 Gold 标注：`multi_03` 的 PD-004（草稿）→ supporting；`chat_03` 的 FN-003（无抬头/税号条款）→ supporting，gold 改为 FN-012；`term_04` 的 PD-022/PD-002（补充提及）→ supporting，gold 只保留 PD-019。
- 详见 `problem/2026-10-31_Gold覆盖率与权限边界冲突.md`。

### 2. Judge 稳定性量化

- 新增 `--judge-stability [N]`：对同一批已存回答重复判分 N 次（默认 3），逐题统计 score / facts / faithful / refusal 一致率与多数票指标，输出 `build/eval/report_stability.json/md`。
- 新增 `--judge-repeats N`：复判时每题重复 N 次，先按分数取众数、再按事实点状态组合取众数，写入 `results_rejudge.jsonl` 的 `judge_repeat_scores`；权威基线使用 **3 次**。
- 关键观测：同一回答在 temperature=0 下跨批次仍会翻转；`ver_02` 定向批次为 2/2/2，全量批次出现 1；`perm_01` 为 1/1/1 与 1/1/2 混合。**分数比事实归因稳定，单次判分不能当权威基线。**
- 3 次众数结果：分数一致率 **58/60 = 0.967**；不一致题只有 `ver_02`（`[1,2,1]`）与 `perm_01`（`[1,1,2]`），均取众数 1。

### 3. Judge 误判修复（派生问题）

- **JSON 解析失败**：`multi_04` 的 judge 把回答里的原文引号直接塞进 JSON，`json.loads` 报错，temperature=0 下 3 次重试拿到同样的坏 JSON。新增 `_parse_judge_json` / `_escape_inner_quotes`，解析失败时只转义字符串内部非结构性的 `"` 再重试。修复后 `multi_04` 5 个事实点全 covered、score=2。
- **标识符数字污染**：`V1`、`V3.2.2`、`HR-002`、`S1` 里的数字曾被当作事实数量。新增 `_claim_numbers` 先剔除标识符再抽数量，`18K`、`71/86`、`2025-10` 保留。

## 重要决策与细节

- **权限边界不妥协**：HR-010 不进普通员工检索是设计目标；Gold 标注应区分“必答来源”和“补充/不可见来源”，不能为了覆盖率指标放宽权限。
- **先查指标实现，再查系统**：覆盖率缺口的首要根因之一是诊断脚本的首次命中排名写错；改指标/标注同样要做原文、权限与全量差分校验。
- **不为单题加规则**：`ver_01` / `perm_01` / `ver_02` 都不写单题特判；`ver_02` 的否定句找回也没有加“不具执行效力→不能作为依据”这类单题同义词，避免污染通用性。本轮新增规则同样只写通用维度（引用核对、旧版并列、字段逐行、完整性），不写题号。
- **重复判分取众数**：3 次投票的成本可控（60 题约 180 次 judge 调用），比反复重跑单题挑分更可复现；稳定性模式单独保留，用于后续量化。
- **生成温度改为 0**：0.1 温度下同一提示词多次生成的内容与引用都不稳定（见第 4 节证据），单样本全量分噪声大；改 0 后目标题 3 次抽样稳定。judge 仍取 3 次众数，因为 temp=0 下仍有单题翻转（`fact_08` `[2,1,2]`）。
- **规则要能落地**：此前的“规则写了但没生效”主因是温度波动，不是规则不够具体；先量化生成稳定性，再判断提示词改动是否有效。

## 已知问题

1. **judge 对复合事实的取句粒度**：judge 要求 `quote` 是回答中的连续片段，跨两条的复合事实容易被判 missing。单次判分曾把 `ver_01 K3`、`agg_08 K3` 判 missing（答案实际已覆盖），靠 3 次众数和措辞调整后消失；未改 judge 逻辑，避免为个例放宽标准。后续可考虑“按子句拆分校验”，需先做全量差分。
2. **引用错标仍有残余风险**：temp=0.1 下 `chat_02` 3 次抽样有 2 次把 IM-018 的原话标成 [IM-004]；改为 temp=0 并加引用核对规则后 3/3 正确，但“多个群聊/纪要并存”的场景仍是风险点。
3. **可复现性仍非严格确定**：temp=0 下生成明显更稳，但 judge 仍有单题翻转（`fact_08` `[2,1,2]`），所以权威基线继续用 3 次众数，不退回单次判分。
4. **否定句的确定性找回有边界**：为避免反义误判，含否定词的事实不走实词覆盖兜底；后续若再出现同类漏判，可考虑“否定主语 + 极性一致”的通用规则，但需先做全量差分。
