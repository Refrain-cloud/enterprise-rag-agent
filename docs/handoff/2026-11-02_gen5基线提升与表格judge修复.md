## 2. `--gen-repeats` 逐轮判分取众数

改动位置：`eval/run_eval.py:1120-1155`、`eval/run_eval.py:1349-1362`。

- 旧行为：只判第一轮生成，其余轮次各判一次用于漂移统计；基线分数由“哪一轮排在前面”决定。
- 新行为：
  1. 每一轮生成都用 `judge_repeats` 次判分，轮内先取众数；
  2. 再用 `_modal_index` 跨轮取众数，先按分数、再按事实点状态组合，平票保留最先出现的一轮；
  3. 代表性轮次的回答用于 `retrieved_ids`、`sources`、`cites_gold`、泄漏与拒答指标；
  4. 逐题记录 `generation_scores`、`generation_representative` 和 `generation_answers`。
- 成本口径：判分调用数为 `gen-repeats × judge-repeats`，帮助文本已更新。
- 冒烟验证：`fact_24`、`ver_17` 各生成 3 轮，`generation_scores=[2,2,2]`，均分 2.0。
  产物：`build/eval/report_gen3_check.json`、`results_gen3_check.jsonl`。

## 3a. md/文本表格确定性核算

改动位置：`src/tools/text_table.py`。

- 白名单新增 `md`、`txt`，md 月报与文本表格可进入确定性核算。
- 解析器支持“表头 / 空行 / 分隔行 / 空行 / 数据行”，表头不再要求以 `|` 开头；遇到下一张表的表头会终止当前表，不再吞掉后续表格。
- 多表文档按**列结构签名**分组：同构表（扫描件续页）合并，异构表（发票购买方表 / 货物明细表）分别核算，第一张能算出结果的表生效。
- 分组列改为**实体优先、行标签兜底**：有“一号工厂”这类实体行时按实体聚合；普通 md 表按行标签去重数选择分组列。纯数字、百分比、带标点或超过 20 字的文本不作为分组名。
- 单独识别 `合计/总计/小计/汇总/总额/共计/总成本/总费用` 行：从明细中剔除，作为 `declared_total` 与逐行合计对照。
- 普通（非实体）表加严格闸门：必须同时满足“题目点名唯一数值列 + 表内存在合计行 + 明确问合计/汇总”，避免把 `scan_05` 这类多字段题误算成一个总额。
- 单位优先取表头括号（`本月(元)`）或字段名提示（金额/费用/成本 → 元）；金额保留小数，不再被 `:g` 截成 6 位有效数字。

| `SC-007` 发票明细金额合计 | 552406.08 元，与表尾一致 |
| `scan_05` 多字段发票题 | 仍回退 RAG（未被误算） |

| `agg_16` 混合叙述题 | 仍回退 RAG（含“主要异常”，按设计） |

## 3b. judge 日期与金额等价写法

改动位置：`eval/run_eval.py:382-449`。

- 新增 `_numeric_values()`：从原文抽取数值，`万/亿` 归一成基本单位，返回数值集合。
- `_number_in()` 现在接受**原文**（保留小数与单位），先做原有字符串/分段比较，再做数值比较；调用点从 `_canon(window)` 改为 `window`。
- `_claim_numbers()` 把带“万/亿”的数量换算成基本单位（`11.1 万元` → `111000`），保证正反两个方向都能命中。
- 矛盾检测复用同一数值集合，`2026-09-16` 与 `2026年9月16日`、`11.1 万元` 与 `111,000 元` 不再被判为数字冲突。
- 新函数加入 judge 指纹覆盖，判定语义变化可被追踪。

验证：

|---|---|
| `09` vs `2026年9月16日` | 命中 |
| `111000` vs `11.1 万元` / `111,000 元` | 双向命中 |
| `agg_14` 用中文日期回答复判 | 4 个必答点全部 covered，2 分 |

## 重要决策

- **生成漂移不“跑到过为止”**：五道真实遗漏题保留 1 分，只有 judge 噪声（`ref_09`）用 judge×3 众数并入基线。与 gen4 对 `multi_02`、`fact_23`、`agg_11` 的处置口径一致。
- **多轮生成取众数必须逐轮判分**：只判第一轮会把“哪一轮恰好排在前面”写进基线；`gen-repeats` 的语义应为“多轮生成 + 每轮判分 + 跨轮众数”。
- **普通表格宁缺毋滥**：非实体表必须同时满足唯一数值列、合计行、明确求和诉求，否则回退 RAG。确定性核算只能覆盖口径明确的题。
- **judge 数值比较保留上下文闸门**：只放宽数字写法，不取消事实点窗口和二字词覆盖率要求，避免“答案里出现过这个数字”就判覆盖。
- **md 表格与 judge 改动都会改变指纹**：本轮全量重跑已获确认；后续再改 `max_tokens` / judge 语义仍需先估算再全量。

## 已知问题

1. **两处 900 token 截断**：`multi_04`、`multi_09` 的 `completion_tokens` 恰好 900，答案中途截断。`src/agent/ask.py:236` 默认 `max_tokens=900`（仅表头金额题放宽到 1200）。修复会改变回答指纹，需重新全量。
2. **五道生成遗漏题**：`ref_03`、`multi_04`、`agg_11`、`perm_12`、`multi_09`。其中两道的根因是截断，其余是生成时少写对比项/建议项。
3. **gen5 单次均分低于 gen4 合并基线**：不是检索/工具回归；gen4 是多次局部重跑合并的结果，gen5 是新的单次全量。跨基线比较应看检索、引用、忠实、权限等稳定性指标。
4. **judge 数值等价可能过宽**：同一数值出现在回答其他位置也可能命中；目前仍由事实点窗口和词覆盖率兜底。后续如出现误判，优先收紧上下文窗口，不回退单位换算。
5. **格式检测 26/102（仅观察）**：比 gen4 的 23/102 多 3 题，来自生成措辞变化；自动重写仍关闭。
6. **合并报告的费用口径**：`ref_09` 行保留原单次 `judge_usage`，合并报告的 1.2515 元不含额外两次 judge 调用；本轮实际花费以 1.47 元为准。
7. **`--gen-repeats 3` 成本约为单次的 3 倍生成 + 3 倍判分**：全量约 3.7 元，只建议在漂移排查时按 `--ids` 使用。

## 下一步（按优先级）

1. **处理 900 token 截断**：多段式问题提高 `max_tokens`，或在生成层检测截断并降级重答；改完需全量重跑并重新提升基线。
2. **观察五道遗漏题**：用 `--gen-repeats 3 --ids` 判断是真稳定遗漏还是采样漂移；不要为了 2 分反复重跑。
3. **启动 M2 服务层**：LangGraph 路由、FastAPI、Web Demo（`src/api`、`src/ui` 目前不存在）。
4. **补充表格题覆盖**：评估集只有 `scan_04` 走 table 路由；可为 `IT-014` 增加纯汇总题，验证 md 表格在正式评估中的路由与扣分。
5. **可选**：积累 `--gen-repeats 3` 的稳定性基线，量化多轮生成对分数分布的影响。

## 运行/测试命令

```bash
# 日常 120 题（judge×1，单轮生成）
PYTHONIOENCODING=utf-8 python -m eval.run_eval --judge-repeats 1

# 出稿验收（judge×3）
PYTHONIOENCODING=utf-8 python -m eval.run_eval --judge-repeats 3

# 多轮生成（每轮判分，跨轮取众数；判分调用数 = gen × judge）
PYTHONIOENCODING=utf-8 python -m eval.run_eval --gen-repeats 3 --judge-repeats 1

# 非满分题离线复判（复用已存回答，不调用问答模型）
PYTHONIOENCODING=utf-8 python -m eval.run_eval --rejudge \
  --results build/eval/results_v4_gen5.jsonl --ids ref_09 --judge-repeats 3

# 把局部结果并入基线
PYTHONIOENCODING=utf-8 python -m eval.run_eval --merge-partial \
  --partial build/eval/results_rejudge.jsonl --results build/eval/results.jsonl \
  --ids ref_09

# 从结果重建报告（不调用模型）
PYTHONIOENCODING=utf-8 python - <<'PY'
import json
from pathlib import Path
from eval.run_eval import _aggregate, _write_outputs
directory = Path("build/eval")
rows = [json.loads(line) for line in (directory / "results.jsonl").open(encoding="utf-8")]
source = json.loads((directory / "report_v4_gen5_raw.json").read_text(encoding="utf-8"))["questions_file"]
report = _aggregate(rows, source)
_write_outputs(report, directory, "report", "results.jsonl")
_write_outputs(report, directory, "report_v4_gen5", "results_v4_gen5.jsonl")
PY
```
