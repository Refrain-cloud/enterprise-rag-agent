## 1. 模块拆分与单轨路径

```
src/agent/runtime.py   提示词、上下文拼接、截断重答、来源/草稿/字段校验（从旧 ask.py 原样迁出）
src/agent/state.py     AgentState、TraceEvent、initial_state、trace_event
src/agent/nodes.py     prepare / retrieve / guard / route / structured / generate / self_check / finalize
src/agent/graph.py     build/compile 缓存、条件边、run_agent()
src/agent/ask.py       answer() 门面 + CLI
src/api/main.py        FastAPI 应用、并发控制、静态 UI 挂载
src/ui/                纯静态页面（无 CDN、无构建）
eval/trajectory.py     轨迹指标聚合（纯函数）
tests/                 runtime / nodes / API 单元测试
```

- `answer(question, role, top_k, request_id)` 签名与返回键保持兼容，新增 `citations`、`self_check`、`trace`、`trace_meta`、`rewrite`、`retrieval`、`terminal`。
- eval 与 API 都调用同一个 `answer()`，避免“评估过的路径”和“线上路径”分叉。

## 2. 状态图与保真

图结构：

```
START → prepare → retrieve → guard
guard: terminal → finalize → END
      : 否则 → route
route: structured → structured ─成功→ self_check
                              └失败→ generate
      : rag        → generate
generate → self_check → finalize → END
```

保真处理：

- `retrieve` 复刻原三次检索顺序：基础 `top_k`；聚合题且无可用表格时用 `max(top_k, AGG_TOP_K)`；`best_overall` 用 `top_k=1, ignore_permissions=True`。
- `guard` 复刻原顺序：无命中时先判断越权（拒答）再判断“未找到”；有命中但最优匹配为 dept 机密时拒答。
- `structured` 先 `answer_with_tables`，失败再 `answer_with_scanned_tables`；来源只取 `table_doc_ids`。
- `generate` 的系统/用户提示词、表头题预算和截断重答逻辑与重构前一致。
- `finalize` 只对 RAG 答案补草稿声明。
- `self_check` **只观察不改写**：空答案、引用 doc_id 是否可追溯、denied 与 sources 是否矛盾。
- 零命中改写默认开启（`RAG_REWRITE_ON_EMPTY=1`），仅在无命中且最优匹配未被权限拦截时触发一次；越权拒答先于改写。

## 3. Trace、self_check 与轨迹指标

- `TraceEvent = {node, seq, elapsed_ms, status, summary, error}`；每节点只返回增量字段，`trace` 用 `operator.add` 汇总。
- `trace_meta` 含 `request_id / total_ms / nodes`；顶层另含 `retrieval.calls / retrieval.queries / rewrite`。
- `self_check = {ok, empty_answer, citations_total, unresolved_citations, denied_consistent, findings[]}`。
- `eval/trajectory.py` 汇总：路由分布、与 `build/eval/route_reference.json` 的路由一致率、结构化尝试/回落、改写触发/成功、自检告警与 finding 类型、节点平均耗时。
- 路由参考快照从 v5 `results.jsonl` 生成，不改题库。

## 4. FastAPI 与并发

- `POST /api/ask`：`question` 1–500 字、`role` 服务端校验并归一化、`top_k` 1–20、`debug` 控制是否返回 trace/self_check。
- `GET /api/health`、`GET /api/roles` 不调用模型。
- 并发：`Semaphore(API_MAX_CONCURRENCY=4)`；排队 5s 超时返回 429；执行 120s 超时返回 504；其他异常返回 500 且只给 request_id，不泄漏堆栈。
- 请求级用量：`src/llm.py` 用 `ContextVar` 保存可变 list，`asyncio.to_thread` 复制上下文时共享同一 list；全局 usage 继续供 eval 使用。
- lifespan 预热 `jieba`、检索资源与表格语料；索引缺失时 `/api/health` 可见 `warmup_error`。
- 静态 UI 在 API 路由之后挂载；同源，无 CORS；响应带 CSP、`X-Content-Type-Options`、`X-Frame-Options`。

## 重要决策

- **单轨而非双轨**：`answer()` 直接走 LangGraph，服务与评估共用；新增 agent 代码会让旧回答指纹失效，因此必须全量重跑一次。
- **不启用 checkpointer**：当前是单轮无状态问答，持久化只会引入序列化与并发问题；多轮会话后置。
- **self_check 只观察不改写**：避免自动重生成掩盖问题，也避免二次生成带来不可控成本；先积累告警分布。
- **API 只做薄封装**：路由、工具、权限、版本判断全部留在 agent 层，API 不复制业务逻辑。
- **并发先限 4**：Chroma/BM25 只读共享；需要更高并发时先压测再加锁或换服务形态。
- **后台任务停止不等于完成**：全量结果必须核对 `fingerprints.answer` 与当前 `_answer_fingerprint()`；提升基线使用独立输出文件名，避免旧进程覆盖。

## 已知问题

1. **单次全量 2.0 只代表一次采样**：`ver_17`、`agg_11`、`fact_15`、`fact_23`、`ref_08` 在历史上都出现过 1 分或 0 分；回答指纹未变时不要重跑到“满意”，出稿验收用 `--judge-repeats 3`，需要看生成方差时用 `--gen-repeats 3 --ids`。
2. **自检告警 2/114**：`multi_06` 引用 `IM-0019`、`term_04` 引用 `TR-004`，两者都不在本次 hits 中；答案仍被判满分。下一步要区分“检索漏召回”与“模型自行拼接引用”，再决定是否加引用后置校验。
3. **格式检测违规 22/102（仅观察）**：自动重写仍关闭；违规项包括 `日期`、`项目经理`、`编号` 等短字段，是否开启重写需要先量化其对答案质量与成本的影响。
4. **`role` 由客户端传入**：API 只校验取值在 `ROLES` 内，没有登录态；生产环境必须从会话派生角色，否则可伪造角色绕过权限。
5. **超时后线程不会立即停止**：`asyncio.wait_for` 超时返回 504 后，`to_thread` 的生成线程仍会跑完；高并发下需要可取消的执行模型或任务队列。
6. **UI 未做自动化浏览器测试**：`/`、`/api/health`、`/api/roles`、`/api/ask` 已用 TestClient 与 curl 验证，4 并发也通过了；但点击引用、展开轨迹等交互没有用浏览器自动化跑过，交接前需要人工过一遍。
7. **旧评测进程覆盖结果的教训**：停止后台任务不等于立即退出；提升基线前必须核对回答指纹，并使用独立输出文件名。详见 `problem/2026-11-02_并发评测覆盖基线结果.md`。
8. **工作区仍有未跟踪文件**：`工作流程记录_2026-10-28_2026-10-29.md`、`工作流程记录_2026-10-30.md` 按用户要求不提交。

## 下一步（按优先级）

1. **M3 多轮会话与流式输出**（按计划后置）：需要引入会话状态与 checkpointer，先设计会话隔离与预算上限。
2. **API 鉴权与用户体系**：当前 `role` 由客户端传入，生产环境需要从登录态派生，避免角色伪造。
3. **超时后的线程回收**：`asyncio.wait_for` 超时后 `to_thread` 线程仍会跑完；高并发下需要可取消的执行模型或任务队列。
4. **judge 与生成稳定性**：单次基线只代表一次采样；出稿验收继续用 `--judge-repeats 3`，必要时对不稳定题做 `--gen-repeats 3 --ids` 观察。
5. **引用自检告警治理**：对 `unresolved_citation` 的题，判断是检索漏召回还是模型自行拼接引用，再决定是否加“引用必须来自上下文”的后置校验。
