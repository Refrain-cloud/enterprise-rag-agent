# 表格 SQL/pandas 工具（M1 数据底座）

- 日期：2026-10-29
- 阶段：M1 数据底座
- 状态：完成（规则路由 + SQL 沙箱 + 评估验证）

## 当前进度

在原有“检索 → 问答”链路中加入一条**结构化统计路由**：

- 检索命中 CSV/XLSX，且问题含强聚合意图时，把表格装入内存 SQLite；
- LLM 只负责生成一条 SELECT，沙箱执行；
- 第二次 LLM 调用把查询结果**原样转述**成中文并标注 `[doc_id]`；
- 任何一步失败自动回退原向量问答路径，非聚合问题完全不受影响。

30 题评估中 SQL 恰好命中 4 道结构化聚合题，全部满分；检索指标不退化，引用率提升到 1.000。

## 已完成内容

1. **表加载**（`src/tools/table_loader.py`）
   - 按 doc_id 回查 `build/corpus/docs.jsonl`，校验格式、解析状态并**再次**执行 `can_access`；
   - CSV/XLSX 读取（编码回退、多 sheet 分开）；
   - 表头检测、合计/小计行拆分、千分位/百分比/货币符号清洗。
2. **SQL 工具**（`src/tools/sql_tool.py`）
   - 规则路由（强聚合词 + 表命中）、版本权威性问题禁用路由；
   - 内存 SQLite + `query_only` + `set_authorizer` 沙箱（只允许 SELECT/READ/FUNCTION/RECURSIVE，拒绝写、DDL、ATTACH、PRAGMA、系统表）；
   - SQL 单语句校验、超时与行数上限；
   - 两步 LLM：生成 SQL（失败重试一次）→ 转述结果。
3. **接入主流程**（`src/agent/ask.py`）
   - 权限拒答分支之后尝试工具，成功则返回 `route="sql"`；失败回退 `route="rag"`；
   - 所有返回增加 `route` 字段；CLI 增加 `--debug` 打印路由与 SQL。
4. **评估观测**（`eval/run_eval.py`）
   - 结果记录 `route`、`sql`、`sql_row_count`、`table_doc_ids`；
   - 报告增加 `route_counts` 与分类路由分布，Markdown 增加路由列；
   - 未改动 gold 与指标公式。
5. **问题记录**：`problem/2026-10-29_表格SQL工具数据陷阱.md`（【面试可讲】）。

## 重要决策与细节

- **SQLite 而非 DuckDB**：`sqlite3` 是标准库，`pandas` 已在依赖中，零新增依赖；分析型 SQL 的需求当前数据量用不上 DuckDB。
- **规则路由而非 LLM 分类**：先保证可解释、可评估、零额外调用。首版把“多少/几个”当聚合词，导致 8 题误路由（`ver_02`/`ver_04` 绕过版本推理得 0 分、引用率跌到 0.852）；收紧为强聚合词并加入版本标记保护后，SQL 恰好命中 4 题。该回归由评估直接暴露。
- **合计行拆表**：首列匹配“合计/小计/总计/汇总”的行拆到 `<表>_summary`。明细聚合不再重复计算；问“整体执行率”仍可查汇总表。`MS-009` 取缺口最大值因此不会选中“合计 9”。
- **数值清洗**：千分位/货币符号去除，百分比按百分点存 REAL（77.5 表示 77.5%）；空值写 NULL。
- **权限双保险**：工具不信任检索层结果，按语料元数据再次 `can_access`；普通员工提问 `XS-003`（confidential）时不会载入。
- **SQL 成功但 0 行不回退**：由转述层回答“未查询到符合条件的记录”，避免把合法的空结果交给向量问答猜测。
- **来源只列实际使用**：优先取 SQL 引用到的表，其次答案中 `[doc_id]` 提到的文档；避免把仅加载未使用的表列进来源。
- **多小问提示**：`agg_02` 首次只查汇总行，补充“多小问/排名要查明细、问最高必须返回数值”后，一次 SQL 同时返回整体执行率、最高成本中心、81.1% 与原因。
- **转述模板约束**：只能原样引用结果中的数字；不提及 SQL、数据库或 `t_` 开头的内部表名。

## 已知问题

1. **judge 波动**：`ver_02` 同一答案类可判 0 或 2；judge 偏宽松与偶发严格并存，需人工抽检校准。
2. **日期幻觉**：`ver_02` 中模型声称“当前为 2024/2025 年”、`FN-012` 尚未生效；系统提示词未注入当前日期，是潜在根因，尚未修复。
3. **规则路由的边界**：仍可能漏掉隐式的统计问题；当前只覆盖显式聚合词。
4. **汇总/明细选择依赖提示词**：无法在沙箱层强制；SQL 会记录在结果中供抽查。
5. **数字格式**：工具路径输出 `9530.0`、`4.0`，未做千分位/整数格式化（不影响判分）。
6. **`agg_02` 原因偏短**：仅用 `BG-001` 备注“现场差旅增加”，未引用 `XS-001` 说明中“恒远精工、华中二期现场周期延长”的细节；judge 仍判 2。
7. **无单元测试**：目前只有 `table_loader` 自检与评估；表头检测/数值清洗的后向兼容性靠人工核对。
8. **评估成本未量化**：只记录延迟，未记录 token 用量；两次全量评估期间遇到一次百炼账户欠费报错（已充值解决）。
9. 8 个扫描 PDF 仍无文本层，待 OCR。
10. 角色与部门仍未完全对齐（IM/RD/CS 无对应角色）。
