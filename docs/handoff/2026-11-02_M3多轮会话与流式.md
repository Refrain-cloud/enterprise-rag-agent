## 1. 会话层

- `src/agent/session.py`：`SessionStore` + `Session`/`Turn`/`SessionView`，所有访问走单个 `threading.RLock`，对外返回拷贝。
- 会话 ID 由服务端用 `secrets.token_urlsafe(24)` 签发；未知 ID 返回 404，不静默新建。
- `begin_turn` 原子检查：存在性（404）、角色一致（409）、同会话并发（429）、轮次/token/费用上限（429），随后置 `busy` 并签发本轮 `turn_token`。
- `finish_turn(..., token)` 只在 token 匹配时写历史并清 `busy`；不匹配的晚到 worker 只累计用量，避免污染新一轮历史或清掉新一轮的 busy。
- 过期与会话数：`last_seen` 每次访问刷新，TTL 默认 1800s；`create` 机会式清理，lifespan 另有 300s 后台清理；超过 `RAG_SESSION_MAX_COUNT` 按 LRU 淘汰。
- 默认上限：10 轮、10 万 token、0.5 元/会话；历史答案存储截断 400 字。

## 2. 多轮改写与历史注入

- `prepare` 节点：有历史且 `RAG_FOLLOWUP_REWRITE=1` 时，先用一次低预算模型调用把追问改写成独立检索查询；失败或空结果回退原问题并写入 trace。
- `retrieve` / `route` / `structured` 使用 `rewritten_question or question`；`generate` 仍用原问题，并把最近 3 轮、总长 1200 字以内的历史注入提示词。
- 历史注入前剥离引用标记，块内明确“仅用于理解指代，不得作为引用来源”。
- **无历史不变性**：历史为空时不改写，生成提示词与改造前逐字一致，已有单测锁定；评估路径因此行为不变。

## 3. 流式链路

- `src/llm.py` 新增 `stream_chat_completion()`：`stream=True`、可选 `stream_options.include_usage`；每个 chunk 追加 `delta.content` 并回调；usage 每次调用只记录一次；缺失时按字符数估算并标记 `estimated_calls`。仅在首个 chunk 之前失败才去掉 `stream_options` 重试。
- `src/agent/streaming.py`：`StreamSink` 用 `loop.call_soon_threadsafe(queue.put_nowait, ...)` 把工作线程事件送回事件循环；`emit_status` / `emit_delta` / `emit_reset` 在无 sink 时全部 no-op，评估路径零影响。
- `src/agent/runtime.py`：新增 `generate_rag_answer_stream()`，输出结构与非流式一致；截断重答先发 `reset` 再整段重来；字段校验与草稿声明仍在流结束后执行，**以 `final.answer` 为准**。
- SSE 事件：`meta`、`status`、`delta`、`reset`、`final`、`error`；心跳为 `: ping`（默认 15s）。
- 端点 `POST /api/ask/stream`：先完成会话校验（404/409/429 在开始流之前以 JSON 返回），再取并发许可；worker 负责 `start_request_usage()`、`run_agent(..., stream_sink=sink)`、`finish_turn` 与 `final`；生成器超时（120s）发 `error(504)`，结束时关闭 sink、只释放一次 semaphore。
- 非流式 `POST /api/ask` 增加可选 `session_id`，与会话/流式共用同一 `answer()` 路径。

## 重要决策

- **应用层会话存储，不用 LangGraph checkpointer**：避免把 `trace` / `tool_result` 等瞬时字段持久化造成跨轮污染，图保持无状态。
- **每轮 token 守卫**：客户端中断或超时后线程可能继续跑完；用 turn token 确保晚到结果只累计用量，不写历史、不清新一轮 busy。
- **流式只覆盖生成节点**：denied / not_found / SQL / table 只发状态与最终结果，减少协议分支。
- **最终答案权威**：前端必须用 `final.answer` 覆盖增量文本，避免 finalize/self_check 与流式文本不一致。
- **评估路径无历史**：M3 的改写与历史注入在空历史时完全旁路，保证与 M2 可比。

## 已知问题

1. **`agg_11` 单次非满分**：历史波动题，本次为措辞差异触发 judge 扣分；1.9917 只代表一次采样，不据此转正基线。
2. **会话仅进程内存储**：服务重启即丢失；多 worker 部署会因请求落到不同进程而出现 404。生产需要 Redis/SQLite 等共享存储或粘性会话。
3. **线程不可取消**：客户端断开或超时后生成线程仍会跑完并消耗 DashScope 配额；semaphore 已按流结束释放，但实际负载可能短时高于并发上限。需要任务队列或可取消执行模型。
4. **`role` 仍由客户端传入**：API 只校验取值，无登录态；生产必须从会话派生角色。
5. **手动冒烟观察到 guard 过度拒答**：普通员工问“员工满 5 年不满 10 年，年休假有几天？”返回 denied（`unauthorized_best_match`）。该行为在 M3 之前已存在，非本轮引入；需要单独排查最优命中为何落在机密文档，本轮未修改。
6. **SSE 反向代理未实测**：已设置 `X-Accel-Buffering: no`、禁缓存并加心跳；部署到 Nginx 等代理时仍需确认不缓冲。
7. **流式中间态可能短暂显示字段前缀**：字段清洗在流结束后执行，以 `final.answer` 为准，属于可接受中间态。
8. **工作区未跟踪文件**：`工作流程记录_2026-10-28_2026-10-29.md`、`工作流程记录_2026-10-30.md` 按用户要求不提交。

## 下一步（按优先级）

1. **共享会话存储**：多进程/多实例部署前，将 `SessionStore` 抽象为可插拔后端（Redis 或 SQLite），并补并发测试。
2. **API 鉴权与角色派生**：从登录态生成角色，禁止客户端直接指定。
3. **可取消的生成执行**：用任务队列或可中断执行替代 `to_thread`，解决超时后线程继续跑的问题。
4. **稳定性抽查**：如需确认 `agg_11`，用 `--ids agg_11 --judge-repeats 3`（先确认费用）；不重跑全量。
5. **guard 过度拒答排查**：定位“正常制度问题命中机密文档”的检索路径，判断是元数据过滤还是 guard 判定顺序问题。
6. **部署验证**：在反向代理后验证 SSE 不被缓冲、心跳与超时行为正常。
