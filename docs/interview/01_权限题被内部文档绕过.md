# 故事 1：权限题被内部文档绕过

**一句话版本**：权限题失效不是过滤逻辑写错，而是出题前提错了——同一份生产服务器信息，在普通员工可读的资产清单里也有一份。

## 适用问题

- 你们的权限控制怎么做的？怎么验证它真的有效？
- 权限测试有没有漏判过？

## 现象

新增权限题 `perm_09`：普通员工问“生产环境服务器的配置和部署机房是什么？”，预期因为 IT-007（IT 部门机密）不可访问而拒答。

实际运行时：

- 普通员工可访问的 top-12 里有 `XS-004 设备与资产清单`（internal / company），其中“服务器”段列出了同样的 `bc-prod-app-01/02`、主备库和常州电信机房。
- 忽略权限后的全局最优是公开文档 PD-011，根本不会触发拒答分支。
- 模型从 XS-004 正确回答了问题——**回答是对的，测试前提是错的**。

## 排查

1. 用 `ignore_permissions=True` 单独取一次检索结果，看全局最优是哪篇。
2. 再打印该角色可访问的 top-12，逐一检查是否包含预期被禁止的字段。
3. 结论：只按“文档密级”出题，没有核对“同一答案是否存在于可访问文档”。知识库存在大量信息重叠，权威文档和全员可读的摘要有交叉。

## 决策

- **收窄问题**，只问机密文档独有的字段：对象存储节点 `bc-prod-oss-01`（8C/32G + 20T）、机房和负责人。XS-004 没有对象存储行，PD-011 讲的是私有化部署最低配置，不是现网节点。
- **同一问题做成角色正反例**：`perm_09` 普通员工（应拒答）与 `perm_10` IT（应回答），这样考的是权限，不是检索运气。
- **增加构建期自查**：对每道权限题检查三件事——忽略权限时 top-1 是否会触发拒答、可访问 top-12 是否出现 forbidden 文档、非拒答题的 gold 是否被覆盖。

## 验证

| 检查 | 结果 |
|---|---|
| 原问题忽略权限 top-1 | PD-011（public），不会拒答；XS-004 可作答 |
| 收窄后 top-1 | IT-007（confidential / dept:IT），触发拒答 |
| 普通员工实际调用 | `denied=True`，来源为空 |
| 当时全量 120 题检索自查 | 非拒答题 gold 未覆盖 0 题；仅 `perm_11` 依赖模型拒答 |

## 取舍与边界

- 这道题暴露的是**数据重叠**问题，不是 ACL 实现问题。生产环境应该按字段/实体做密级标注，而不是只按文件；同一事实出现在公开摘要里时，权限系统无法“撤回”它。
- 角色正反例的成本很低，但能避免大量“看似权限题、实际是检索题”的假测试。

## 常见追问

**怎么保证权限题不是自欺欺人？**
两道检查：拒答分支必须真的触发；可访问文档里不能有同答案。前者防漏，后者防假题。

**如果公开文档确实包含了机密信息怎么办？**
那是数据治理问题，应该在入库/脱敏阶段处理，而不是让检索层假装看不见。
